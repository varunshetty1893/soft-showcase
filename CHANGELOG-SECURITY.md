# Security & Data Integrity Changelog

All user-visible behavior changes and security remediations are documented below with their rationale.

## Phase 1 — Authentication & Data Integrity (HIGH)

- **H1 (AUTH_SECRET Hardening)**: Removed hardcoded fallback JWT secret; `lib/config/env.ts` enforces 32+ char secret in production and throws on startup if missing.
- **H2 (Strict Admin Authorization)**: Eliminated hardcoded email string checks in request routing paths; `lib/auth/admin.ts` trusts only DB-backed `isAdmin` flag, with one-time bootstrap on email verification.
- **H3 (Anti-Pre-Hijacking & Anti-Enumeration)**: Replaced direct user creation on registration with `PendingRegistration` staging; duplicate registration returns identical generic response and triggers owner notification rather than revealing user existence.
- **H5 (Production Database Isolation)**: Replaced silent in-memory fallback in `lib/db/client.ts` with strict singleton PrismaClient that throws if `DATABASE_URL` is missing in production; deleted startup auto-seeding.
- **H4 (Provider Contact Privacy)**: Excluded provider `email` and `whatsappNumber` from public project queries, RSC payloads, and saved cart items; contact communication is gated via authenticated, rate-limited channels.

## Phase 2 — Redirects, Rate Limiting & Abuse Prevention (HIGH/MEDIUM)

- **M1 (Open Redirect Defense)**: Implemented RFC & URL-safe origin normalization in `lib/utils/safe-redirect.ts`. Disallows protocol-relative URLs (`//`, `/\`), backslashes, nested encoded sequences (`%2F%2F`, `%2F%5C`), non-http(s) schemes (`javascript:`, `data:`), and redirect loops to auth endpoints (`/login`, `/register`, `/api/auth/*`). Enforced in all auth components and NextAuth `redirect` callback.
- **M2 (Spoofable Client IP Defense)**: `getRequestIp` in `lib/utils/rate-limit.ts` prefers platform-set headers (`x-vercel-forwarded-for` -> `x-real-ip` -> `x-forwarded-for` evaluated at `len - TRUSTED_PROXY_COUNT`), never trusting the client-supplied leftmost hop. When no IP is derivable, hashes User-Agent + Accept-Language into a stricter fingerprint bucket (`fp_${hash}`).
- **M3 (Rate Limiter Hardening & Fail-Modes)**: `createRateLimiter` made purely async to eliminate sync-promise mismatches and memory double-counting. Configured explicit `failMode: "closed"` for authentication/registration/reset endpoints and `failMode: "open"` with warning logs for customer discovery. Standardized `Retry-After` headers on all 429 responses.
- **M4 (Anti-Relay & Anti-Spam Protections)**: Cloudflare Turnstile verification integrated into unauthenticated inquiry and custom request endpoints. Added honeypot verification and 2-second minimum form fill-time check. Enforced per-recipient throttling (3/hr), per-project per-IP throttling (5/hr), and a global daily outbound email cap. Customer confirmations are dispatched only when user identity is verified or CAPTCHA passes.
- **Admin Image Reordering & Primary Cover**: Integrated 4-way arrow controls (Left, Up, Down, Right), "Make Primary" cover toggle, and delete controls into `components/admin/ImageUploader.tsx` with parity to the partner portal.
- **Partner Upload Loading State**: Added dedicated progress state, animated spinner indicators, and skeleton placeholder card during photo uploads in `PartnerSolutionForm.tsx` to provide immediate feedback.
- **Direct Featured Solution Controls**: Added prominent interactive Featured toggle cards with star badges to admin (`ProjectForm.tsx`) and partner forms (`PartnerSolutionForm.tsx`), wired `featured` through edit page initial data, and provided inline toggle in tables.
- **Partner JSON Import Navigation**: Added direct "Import JSON" item to `PartnerSidebar.tsx` and quick action bar in solution creation.

## Phase 3 — Token/Session Hardening & Security Headers (MEDIUM)

- **M5 (Token Hardening & Non-Destructive Rate Limiting)**: Upgraded `verifySecretToken` in `lib/utils/crypto.ts` to use constant-time `crypto.timingSafeEqual` comparison on 32-byte SHA-256 digest buffers, completely removing plaintext comparison fallbacks. Added `attempts` counter to `verification_tokens` and `pending_registrations`; invalid codes increment attempts, and the 5th failed attempt invalidates that specific token. Rate limit triggers now return 429 without destroying valid verification tokens, preventing attacker-driven lockout attacks.
- **M6 (Multi-Device Session Invalidation & Token Versioning)**: Added `tokenVersion` to `User` model, NextAuth JWT payload, and active sessions. NextAuth `jwt` callback cross-references `tokenVersion` against the database on session refresh and purges tokens upon version mismatch. Password update (`/api/user/password`), password reset (`/api/auth/reset-password`), and the new `/api/auth/signout-everywhere` endpoint increment `tokenVersion`, immediately invalidating stale sessions across all user devices. Sensitive endpoints verify `tokenVersion` against the database on each call. Removed `passwordHash` from `authorize()` return payloads.
- **M7 (Strict CSP & Hardened Security Headers)**: Removed `'unsafe-eval'` from production `script-src`. Narrowed `connect-src` to `'self'` and `https://challenges.cloudflare.com` after verifying that third-party endpoints (`wss:`, `*.neon.tech`, `*.upstash.io`) are never invoked by client scripts. Enforced `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `Cross-Origin-Opener-Policy: same-origin`, and `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload` for production. Preserved iframe embedding in development/preview to maintain AI Studio environment functionality.

## Phase 4 — Turnstile, Multi-Layer Rate Limiting, Atomic OTP & Hygiene (N1–N14)

- **N1 (End-to-End Cloudflare Turnstile Integration)**: Created `components/security/TurnstileWidget.tsx` using `next/script` (`strategy="afterInteractive"`, explicit render) with `reset()` imperative handle and wired it into `InquiryForm` (`InquiryModal`) and `CustomProjectForm` for unauthenticated visitors, alongside `aria-hidden` + `tabIndex={-1}` `website` honeypot and mount-time `formSubmittedAt`. Hardened `verifyTurnstileToken` in `lib/utils/turnstile.ts` to fail closed (`errorCodes: ["not-configured"]`) in production if `TURNSTILE_SECRET_KEY` is unset and validate returned `hostname`. Added `frame-src 'self' https://challenges.cloudflare.com` to CSP in `next.config.ts` and required `TURNSTILE_SECRET_KEY` + `NEXT_PUBLIC_TURNSTILE_SITE_KEY` in `lib/config/env.ts` in production runtime.
- **N2 (Three-Layer Provider Lead Protection & Custom Request Isolation)**: Replaced single-bucket `recipientEmailLimiter` with three layers (`providerClientLimiter` 3/hr per provider+IP, `providerCustomerEmailLimiter` 3/day per provider+customer email, and `providerGlobalBurstLimiter` 40/hr per provider). When the 40/hr burst safety layer trips, inquiries are still saved (`201`) with `notificationStatus = "THROTTLED"` (added via additive migration `20261002000001_add_notification_throttled`) while skipping email dispatch. Isolated `/api/custom-requests` to dedicated `custom_email` and `custom_burst` namespaces.
- **N3 (Enforced Daily Outbound Email Cap)**: Added `canSendEmail()` helper in `lib/utils/rate-limit.ts` that consumes `dailyOutboundEmailLimiter` (500/day) once per email sent. When exhausted, records are still saved, email sending is skipped, `notificationStatus` is marked `"THROTTLED"`, and a single `[ALERT][EmailCap]` error is logged.
- **N4 (Strict Production Upstash Enforcement)**: Required `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` in production runtime in both `lib/config/env.ts` and `lib/utils/rate-limit.ts`, restricting the in-memory store strictly to `development` and `test`.
- **N5 (Verified User Password Protection on OTP Confirmation)**: Updated `app/api/auth/verify-otp/route.ts` so that if an existing user already has `emailVerified !== null`, confirming a `PendingRegistration` never overwrites their `passwordHash` or `name`; it deletes the pending row and returns `accountAlreadyExists: true` inside an atomic `db.$transaction` with `P2002` retry handling.
- **N6 (Atomic OTP & Password Reset Attempt Claiming)**: Refactored `app/api/auth/verify-otp/route.ts` and `app/api/auth/reset-password/route.ts` to claim attempts atomically via `updateMany({ where: { ..., expiresAt/expires: { gt: now }, attempts: { lt: 5 } }, data: { attempts: { increment: 1 } } })` prior to hash verification, preventing parallel requests from bypassing the 5-attempt cap.
- **N7 (Upstash Token Reset & Email-Only Reset on Success)**: Implemented `limiter.reset(key)` using `upstashRatelimit.resetUsedTokens(key)` (with `SCAN` + `DEL` fallback) plus memory-store clearing. Updated `lib/auth/auth.ts`, `verify-otp`, and `reset-password` to reset only email-scoped keys on success—never resetting `ip:*` keys.
- **N8 (Login Timing-Parity & Three-Key Lockout Defense)**: Added module-level cost-10 `DUMMY_PASSWORD_HASH` in `lib/auth/auth.ts` so unknown-user and wrong-password paths both execute `bcrypt.compare`. Replaced single login limiter with three layers: per-IP (`30/15m`), per-email+IP (`5/15m`), and global per-email (`25/15m`).
- **N9 (Shared-IP Two-Key Rate Limiters)**: Upgraded `authRegisterLimiter`, `otpVerifyLimiter`, `otpResendLimiter`, `passwordResetRequestLimiter`, `passwordResetVerifyLimiter`, and `partnerRegisterLimiter` to use generous per-IP ceilings paired with strict per-email limits, documented in the policy table in `lib/utils/rate-limit.ts`.
- **N10 (Universal Email HTML Escaping)**: Created `lib/email/escape.ts` (`escapeHtml`), extracted `lib/email/templates/password-reset.ts`, and escaped all dynamic values across all templates in `lib/email/templates/*`.
- **N11 (Strict Production `frame-ancestors`)**: Updated `next.config.ts` so production always emits `frame-ancestors 'none'` and `X-Frame-Options: DENY`, allowing explicit preview origins (`https://*.run.app https://*.google.com https://*.google.dev`) only when `NODE_ENV !== "production"` and `ALLOW_AI_STUDIO_PREVIEW === "true"`, never using bare `*`.
- **N12 (Production Bundle Exclusion for Mock DB)**: Guarded `require("./mock/mock-store")` in `lib/db/client.ts` behind a statically foldable `if (process.env.NODE_ENV !== "production")` check and disabled disk persistence in `mock-store.ts`.
- **N13 (Repository Hygiene)**: Removed stray `.local_mock_store.json`, `*.zip` deliverables, and `.snapshots/`, and added them to `.gitignore`.
- **N14 (Reset-Password Route Consistency)**: Updated `app/api/auth/reset-password/route.ts` to use `await getRequestIp(req)`, handle `error: true` rate-limit results with `503`, and apply atomic attempt claiming (N6).


## Phase 5 — Admin Workflow & Data Integrity Hardening

- **Provider removal drafts published solutions**: `removeProvider` now moves every published project of the provider to `DRAFT` in the same transaction as the soft-removal and its `PROVIDER_REMOVED` audit entry (drafted ids are recorded). Restoring a provider can no longer silently re-publish old solutions without review.
- **Permanent delete requires the typed confirmation**: a blank/incorrect confirmation is rejected by the API (400) and the UI button stays disabled until the provider name (or email) is typed. The `PROVIDER_DELETED` snapshot is now written *inside* the deletion transaction (new `createAuditLogTx`, which never swallows errors), so data is never destroyed without an audit trail.
- **Partner status endpoint persists `adminNotes`** on the provider record, returns 404 for unknown providers, 409 for soft-removed ones (must be restored first), and writes its audit row atomically.
- **Approval/rejection from the main provider table is audited**: the table now uses the audited `/status` endpoint, and the generic provider `PATCH` also writes an audit record (in one transaction with project drafting and role sync) whenever status or activation changes.
- **Transaction verification is reversible**: moving a transaction out of `VERIFIED`/`COMPLETED` clears `verifiedAt`/`verifiedBy`; moving between verified states keeps the original verifier; unknown ids return 404; the audit row (with previous status) is atomic.
- **Bulk project update uses a strict allow-list** (zod `.strict()`): unknown fields are rejected with 400 instead of being copied into Prisma data (also for admin-managed projects), unknown project ids return 404 and write nothing, ids are de-duplicated and capped, categories are validated, publishing requires an active/approved/consented/non-removed provider, and all writes + audit rows run in one transaction.
- **Image ordering/update validation**: reorder rejects duplicate/empty/foreign ids (400) and writes contiguous unique `sortOrder` values; image `PATCH` validates `altText`/`isPrimary`/`sortOrder` (non-numeric `sortOrder` is a 400, not a 500) and swaps the primary flag atomically.
